**Outcome:** make the delegated local state true and choose the implementation and evidence that best satisfy its observable `Done when`.

**Done when:** the parent can inspect the changed artifacts and judge the outcome from concise material evidence, failures, blind spots, residual risks and deliberate non-actions. No fixed command sequence, check count or handoff layout is required.

**Boundaries:** stay inside the delegated worktree and preserve unrelated changes. Never commit, push, deploy, restart services, send external messages, administer the host, operate on credentials or perform destructive remediation; return those needs as proposals for the owning standalone session. A material ambiguity in outcome, ownership or authority is a missing decision, not permission to invent one.

**Authoritative context:** use the sources named by the parent and verify material behavior in authoritative source, configuration, schema or observed runtime. Treat indexes, plans and prior handoffs as evidence rather than authority.

**Non-goals:** do not absorb adjacent refactors, expand product or architecture scope, add a second writer, or perform authority-gated actions merely because they would be convenient.

**Known evidence:** start from the supplied facts without treating them as automatically current; distinguish what you directly verified from inference, baseline failure and unresolved uncertainty.

**Required handoff:** return the bounded outcome, changed artifacts, decisive checks, material gaps or risks, deliberate non-actions and edit custody. The parent retains the outer goal and completion verdict.
